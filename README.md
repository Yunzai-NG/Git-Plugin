# Git-Plugin

Yunzai NG 原生 Git 仓库动态推送插件，支持 **GitHub / Gitee / GitCode**。所有 Token、推送订阅和私有仓库授权均可在现有 NG 面板配置，无须另装面板组件。

## 安装与启用

需要 Yunzai NG **0.7.0+** 和 Node.js **20.11+**。将本目录放在 `<NG 主目录>/plugins/Git-Plugin` 并编译：

```sh
cd <NG 主目录>/plugins/Git-Plugin
pnpm install --ignore-workspace
pnpm run build
```

然后重启 NG，或在面板的插件页扫描并加载。源码目录启动时要包含 `--plugins ./plugins`。

入口为编译产物 `dist/index.js`。`dist/` 不进版本库，**不编译就没有入口**。插件用 TypeScript 编写，没有额外运行依赖；`@yunzai-ng/core` 与 `@yunzai-ng/types` 是 `peerDependencies`，运行时由宿主提供。图片模式使用已安装的渲染器，缺少渲染器时自动发送文字。

插件目录位于框架 checkout 内时，`pnpm install` 必须带 `--ignore-workspace`，否则 pnpm 会把它当作框架工作区的一部分，改写框架根目录的 `pnpm-lock.yaml`。

插件初始订阅为空，不自动向任何群聊或私聊推送。框架源码仓库默认忽略整个 `plugins/` 目录，本插件文件不会自动进入框架主仓库提交；可作为独立插件目录分发。

## 在面板配置

进入 **插件 → git-plugin → 配置**，或配置页中选择 `git-plugin`。

1. **平台 Token**：填写 GitHub、Gitee、GitCode 默认 Token，或添加命名凭据。公开仓库可先留空尝试，部分平台要求认证或限制匿名配额。Token 为各平台自己的个人访问令牌，仅需相应仓库读取权限。
2. **推送订阅 → 添加一项**：选择平台，填写 `owner/repo`，选择事件与样式，再填写机器人账号记录 ID、接收类型与目标 ID。
3. **保存**：配置立即生效。新订阅异步验证仓库并建立基线，首次成功检查不发送历史。用 `#git列表` 或主人命令 `#git状态` 查看初始化及错误情况。

**机器人账号记录 ID 是 NG 的 UUID，不是机器人 QQ 号。** 从账号页获取，或向机器人发送主人命令 `#git状态`，其中会列出账号记录 ID、适配器和账号 ID。群聊目标填群号/平台群 ID，私聊目标填用户 ID。QQ 官方机器人应填其平台 openid。发送始终绑定该账号，不会在离线时换用其他机器人。

| 配置 | 默认值与说明 |
|---|---|
| 总开关 | 开启；关闭暂停抓取和发送，保留已有进度及队列 |
| 检查间隔 | 300 秒，可设 60–86400 秒 |
| 请求超时 | 20 秒，可设 1–120 秒 |
| 默认事件 | `commit, issue, pr, release` |
| 默认样式 | 文字摘要；可选图片卡片 |
| 订阅启用 | 开启；关闭该项只暂停该订阅 |
| 仓库 | 两段 `owner/repo`，面板此字段不填写 URL |
| 分支 | 空值使用默认分支；仅影响 Commit |
| 事件 | 空列表沿用默认事件，也可单独多选 |
| 样式 | 沿用默认、文字、图片 |
| 凭据名称 | 空值用平台默认 Token；命名凭据必须属于相同平台 |
| 订阅上限 | 200 条；每项对应一个机器人账号和接收会话 |

Token 使用密码框，支持替换和清空。沿用 NG 现有配置接口：登录后的管理员能读取真实值，本地 YAML 也保存真实值；修改其他字段不会要求重填 Token。不要把含 Token 的配置文件公开。插件状态、聊天回复和错误日志不打印凭据或远端错误响应。

聊天和面板共用 `config/git-plugin.yaml`。聊天新增后重新读取面板配置即可编辑；管理者同时操作时，请在编辑列表前重新读取。现有面板整体保存订阅数组，最后一次保存为准。编号根据平台、仓库、分支、账号和目标生成，可通过 `#git列表` 获取。

修改备注、样式、Token 不重建基线；新增事件类型独立建立基线，移除类型同时移除其待发送消息。修改仓库、分支或目标按新订阅初始化。删除订阅清理状态和队列；暂停期间的新增在恢复后继续检查。

## 私有仓库

主人先配置 Token，再在 **私有仓库授权** 添加平台、仓库、凭据名称和允许接收的会话。订阅的仓库、凭据、账号及目标必须与授权匹配；默认 Token 对应空凭据名称。

公开订阅先匿名验证仓库公开性，然后使用 Token 查询。GitCode 等平台如果连公开元数据都返回 401，则使用已配置的 Token 读取仓库元数据，并要求明确的公开标记；Token 能访问私有仓库不等于允许推送。私有仓库必须有显式会话授权；查询和发送前重新检查权限，撤销授权将清理该会话待发送的私有动态。公开查询会过滤平台标记为私密/受限的 Issue 等条目。私有仓库授权允许向对应会话发送凭据可读的仓库动态。

群管理员不能在聊天中指定任意 Token 或命名凭据，命令仅选择主人已授予本会话的凭据；有多个匹配授权时，请主人在面板指定。平台无法验证公开性且没有显式授权时，订阅会显示失败而不会尝试绕过访问限制。

配置示例见 [`config.example.yaml`](./config.example.yaml)。

## 聊天命令

| 命令 | 说明 |
|---|---|
| `#git帮助` | 所有人可查看帮助 |
| `#git订阅 github:owner/repo` | 订阅当前会话，采用默认事件和样式 |
| `#git订阅 https://gitee.com/owner/repo 分支=main 事件=commit,release 样式=图片` | 完整参数示例 |
| `#git订阅 gitcode:owner/repo` | GitCode 订阅 |
| `#git列表` | 当前会话编号、初始化状态、待发数量与最近错误 |
| `#git取消 <16位编号>` | 删除订阅 |
| `#git检查 [编号]` | 立即检查；不绕过暂停、限流和互斥限制 |
| `#git样式 <16位编号> 文字` | 可改为 `图片` |
| `#git状态` | 主人查看全部订阅和机器人账号记录 ID |
| `#git列表 全部` / `#git检查 全部` | 主人全局管理 |

主人管理全部；群主和群管理员仅管理本群；私聊管理仅主人可用。普通成员不能增删订阅，频道场景暂不支持。重复添加同仓库、分支、账号、目标会更新选项；未填写的可选项恢复命令默认值。

## 图片卡片与头像

图片样式是 600px 宽、2 倍清晰度的卡片，每条动态带作者头像和类型标记。设计说明与对比度见 [`DESIGN.md`](./DESIGN.md)。

- 头像由插件自己下载后内嵌进卡片，渲染器不联网。只从各平台官方头像 CDN 下载，不带 Token，不跟随重定向，只接受 PNG/JPEG/GIF/WebP 且不超过 200KB。
- 头像缓存 6 小时；下载失败的地址 10 分钟内不再尝试。头像取不到时显示作者首字母，不影响出图。
- GitCode 的 Commit 接口不提供作者头像，GitHub 上未关联账号的 Commit 也没有，这两种显示首字母。
- 部署环境访问不到头像 CDN 时，头像并行下载，卡片最多多等 5 秒（单个请求的超时）后用首字母出图；之后 10 分钟内同一地址不再等待。

## 动态与投递语义

- 仅通知**新 Commit、新 Issue、新 PR、新 Release**。Issue/PR 的后续编辑、关闭、合并、评论和评审不会触发通知。轮询间创建后被删除的内容无法发现。
- Commit 使用 SHA 和历史边界，不依赖作者日期。强制推送导致边界消失时保留旧进度并报错；确认后取消并重新订阅可以建立新基线。默认分支切换为无共同边界的历史也按此处理。
- Release 排除草稿、包含预发布版，优先使用发布时间；GitCode 等没有发布时间时使用创建时间。这类平台无法可靠区分创建时间很早、刚公开的草稿。
- 每个订阅每类事件每轮最多查询 3 页，每页 100 条，扫描状态持久化，后续轮次继续。Release 为发现旧草稿的新发布会遍历全部发行版。请求只共享于同一轮、相同仓库/分支/凭据范围。
- 每批最多 10 条，每个订阅每轮最多 3 批。内容含仓库、类型、标题、作者、UTC+8 时间和链接，图片带文字链接。每种事件暂存及每个订阅待发队列上限各为 20000 条，达到上限会报告并暂停推进，不静默丢弃。
- 消息与抓取进度一起持久化，发送返回 `ok: true` 后确认出队。账号离线或发送失败保留重试，各群独立确认。只有完成仓库权限验证后才会发送，包括旧队列。
- 采用**至少一次投递**：进程在消息已发出、确认尚未落盘时崩溃，恢复可能重发该批次。HTTP 限流遵守服务端退避时间；普通网络/服务端错误采用指数退避。
- 检查状态位于框架 KV 的 `plugin:git-plugin:` 命名空间。需要重启恢复时应使用持久化 KV 驱动；框架 `memory` 驱动关闭进程即丢失状态。

## 开发验证

框架发布到 npm 之前，需要先构建并链接本地框架 checkout（本插件的 tsc 读取框架的 `dist/*.d.ts`）：

```sh
cd <框架 checkout>
pnpm install
pnpm run build

cd plugins/Git-Plugin
pnpm install --ignore-workspace
pnpm run link:framework   # 在 node_modules/@yunzai-ng 下建立指向框架的链接
pnpm run verify           # build → typecheck:test → lint → test
```

`link:framework` 按 `YZNG_FRAMEWORK` 环境变量 → `../yunzai-ng` → `../../yunzai-ng` → `../../code` 的顺序查找框架仓库，目录布局不同时设置该环境变量。

测试用 vitest，与源码放在同一目录（`src/*.test.ts`），包含平台响应模拟、分页恢复、队列故障、权限、配置热变更、头像下载与过滤、图片回退，以及真实 NG 内核的面板 API 和消息路由集成测试。集成测试把插件源码复制到系统临时目录，由 `createApp()` 加载，只监听本机临时端口，Git HTTP 和消息适配器都是模拟的，不访问实际群聊。

GitCode 接口依据：https://docs.gitcode.com/docs/apis/ ，API 基址为 `https://api.gitcode.com/api/v5`，使用 `Authorization: Bearer <token>`。GitHub 与 Gitee 分别使用 `https://api.github.com`、`https://gitee.com/api/v5`。仓库重命名等重定向不会自动携带 Token 跟随，应修改订阅地址。
