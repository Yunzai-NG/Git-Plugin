# Git-Plugin

Yunzai NG 原生 Git 仓库动态推送插件，支持 **GitHub / Gitee / GitCode**。所有 Token、推送订阅和私有仓库授权都可在现有 NG 面板中配置，无须另装面板组件。

## 安装与启用

需要 Yunzai NG **0.7.0+** 和 Node.js **20.11+**。将本目录放在 `<NG 主目录>/plugins/Git-Plugin` 并编译：

```sh
cd <NG 主目录>/plugins/Git-Plugin
pnpm install --ignore-workspace
pnpm run build
```

编译后重启 NG，或在面板的插件页扫描并加载插件。从源码目录启动时，需要带上 `--plugins ./plugins`。

插件入口是编译产物 `dist/index.js`。`dist/` 不纳入版本库，**不编译就没有入口**。插件用 TypeScript 编写，没有额外运行依赖；`@yunzai-ng/core` 与 `@yunzai-ng/types` 是 `peerDependencies`，运行时由宿主提供。图片模式使用已安装的渲染器，缺少渲染器时自动发送文字。

插件目录位于框架 checkout 内时，`pnpm install` 必须带 `--ignore-workspace`，否则 pnpm 会把它当作框架工作区的一部分，改写框架根目录的 `pnpm-lock.yaml`。

插件初始订阅为空，不会自动向任何群聊或私聊推送。框架源码仓库默认忽略整个 `plugins/` 目录，因此本插件文件不会自动纳入框架主仓库的提交；本插件可作为独立目录分发。

## 在面板配置

在面板 **插件** 页找到 git-plugin 卡片，点 **配置**。

推送按**会话**配置：一个群聊或私聊是一项，在这一项里添加它要接收的仓库。

1. **平台 Token**：填写 GitHub、Gitee、GitCode 的默认 Token，或添加命名凭据。订阅公开仓库时可先留空尝试，但部分平台要求认证或限制匿名配额。Token 是各平台的个人访问令牌，只需相应仓库的读取权限。
2. **推送订阅 → 推送会话 → 添加一项**：填写机器人账号记录 ID、接收类型（群聊或私聊）和群号或用户 ID，备注可写群名。
3. **订阅的仓库 → 添加一项**：选择平台，填写 `owner/repo`，按需填写分支、事件和样式。一个群要推多个仓库，就在这里继续添加。
4. **保存**：配置立即生效。插件会异步验证新仓库并建立基线，首次成功检查不发送历史动态。用 `#git列表` 或主人命令 `#git状态` 查看初始化及错误情况。

**机器人账号记录 ID 是 NG 的 UUID，不是机器人 QQ 号。** 可从账号页获取，也可向机器人发送主人命令 `#git状态`，回复会列出账号记录 ID、适配器和账号 ID。群聊目标填群号或平台群 ID，私聊目标填用户 ID。QQ 官方机器人应填其平台 openid。消息始终由指定账号发送，该账号离线时不会换用其他机器人。

| 配置 | 默认值与说明 |
|---|---|
| 总开关 | 开启；关闭暂停抓取和发送，保留已有进度及队列 |
| 检查间隔 | 300 秒，可设 60–86400 秒 |
| 请求超时 | 20 秒，可设 1–120 秒 |
| 默认事件 | `commit, issue, pr, release` |
| 默认样式 | 文字摘要；可选图片卡片 |
| **会话**：启用此会话的推送 | 开启；关闭后此会话下的仓库全部暂停，进度与队列保留 |
| **会话**：备注 | 可写群名，方便在面板里认出是哪个群 |
| **会话**：机器人账号、接收类型、群号/用户 ID | 同一个机器人的同一个会话只能有一项 |
| **仓库**：启用 | 开启；关闭只暂停这一个仓库 |
| **仓库**：仓库 | 两段 `owner/repo`，面板此字段不填写 URL |
| **仓库**：分支 | 空值使用默认分支；仅影响 Commit |
| **仓库**：事件 | 空列表沿用默认事件，也可单独多选 |
| **仓库**：样式 | 沿用默认、文字、图片 |
| **仓库**：凭据名称 | 空值用平台默认 Token；命名凭据必须属于相同平台 |
| 订阅上限 | 所有会话的仓库合计 200 个；同一会话里同一仓库同一分支只能有一个 |

Token 在密码框中填写，支持替换和清空。插件沿用 NG 现有配置接口：登录后的管理员能读取真实值，本地 YAML 也保存真实值；修改其他字段时无须重填 Token。不要公开含 Token 的配置文件。插件状态、聊天回复和错误日志不会输出凭据或远端错误响应。

聊天和面板共用 `config/git-plugin.yaml`。在群里用 `#git订阅` 添加的仓库会放进这个群对应的会话；还没有这个会话时自动新建一项。用 `#git取消` 删掉一个会话的最后一个仓库时，没写备注的会话会一并删除，写了备注的保留。多人同时管理时，请在编辑前重新读取配置；面板会保存整个会话列表，以最后一次保存为准。

订阅编号根据平台、仓库、分支和会话（账号、接收类型、目标）生成，可通过 `#git列表` 获取。修改备注、样式或 Token 不会重建基线；新增的事件类型会独立建立基线，移除类型时也会移除该类型的待发送消息。修改仓库或分支、或把仓库移到另一个会话，都按新订阅初始化。删除订阅会清理状态和队列；恢复订阅后，会继续检查暂停期间新增的动态。

**0.3 是破坏性更新，不迁移旧配置。** 旧版平铺的 `subscriptions` 会被丢弃，请升级前自行备份配置，升级后在「推送会话」中重新添加群聊或私聊及其仓库。未重新配置的旧订阅不再推送，相关进度与待发队列会被清理；平台 Token、命名凭据及私有仓库授权仍保留。新订阅首次成功检查只建立基线，不补发旧动态。

## 私有仓库

主人先配置 Token，再在 **私有仓库授权** 中添加平台、仓库、凭据名称和允许接收的会话。订阅的仓库、凭据、账号及目标必须与授权匹配；使用默认 Token 时，凭据名称留空。

配置了平台默认 Token 或命名凭据时，插件直接使用对应 Token 查询仓库元数据和动态，不再先进行匿名探测，避免额外消耗同一出口 IP 的匿名配额。未配置 Token 时才匿名访问；认证失败不会降级为匿名重试，限流时仍遵守平台退避时间。不论使用哪种方式，公开推送都要求元数据中有明确的公开标记。Token 能访问私有仓库，不代表允许推送。私有仓库必须有显式会话授权，插件会在查询和发送前重新检查权限；撤销授权后，会清理该会话待发送的私有动态。公开查询会过滤平台标记为私密/受限的 Issue 等条目。私有仓库授权允许向对应会话发送凭据可读的仓库动态。

群管理员不能在聊天中指定任意 Token 或命名凭据，聊天命令只会选择主人已授权给本会话的凭据；有多个匹配授权时，需要主人在面板中指定。无法通过平台验证仓库公开性、且没有显式授权时，订阅会显示失败，不会尝试绕过访问限制。

配置示例见 [`config.example.yaml`](./config.example.yaml)。

## 聊天命令

| 命令 | 说明 |
|---|---|
| `#git帮助` | 所有人可查看帮助 |
| `#git订阅 github:owner/repo` | 订阅当前会话，采用默认事件和样式 |
| `#git订阅 https://gitee.com/owner/repo 分支=main 事件=commit,release 样式=图片` | 完整参数示例 |
| `#git订阅 gitcode:owner/repo` | GitCode 订阅 |
| `#git列表` | 当前会话图片列表：编号、状态、事件、推送样式、待发数量与最近错误 |
| `#git取消 <16位编号>` | 删除订阅 |
| `#git检查 [编号]` | 立即检查；不绕过暂停、限流和互斥限制 |
| `#git样式 <16位编号> 文字` | 可改为 `图片` |
| `#git状态` | 主人查看全部订阅和机器人账号记录 ID |
| `#git列表 全部` / `#git检查 全部` | 主人全局管理 |

主人可管理全部订阅；群主和群管理员只能管理本群订阅；私聊中的管理命令仅限主人使用。普通成员不能增删订阅，暂不支持频道场景。重复添加仓库、分支、账号和目标均相同的订阅时，会更新其选项；未填写的可选项会恢复为命令默认值。

## 图片卡片与头像

图片样式是 600px 宽、2 倍清晰度的卡片，每条动态带作者头像和类型标记。设计说明与对比度见 [`DESIGN.md`](./DESIGN.md)。

从 0.3.2 起，`#git列表` 默认生成与动态卡片同样风格的图片，主人使用 `#git列表 全部` 查看全部会话。列表显示仓库、平台、分支、实际事件、推送样式、状态、待发数量、最近检查和错误；每张图最多 5 个订阅，自动分页，底栏只保留 Git-Plugin 和 Yunzai NG 的运行版本。

列表图片不受订阅的文字／图片推送设置影响；缺少渲染器或渲染失败时回退文字。图片下方附完整的可复制订阅编号，方便执行取消、检查和样式命令。查看列表只读本地状态，不触发仓库检查。`#git状态` 保持文字诊断输出。

Commit 推送分开展示**提交标题、详细正文、变更详情**：

- 提交消息第一行作为标题，其余部分保留换行作为正文，不把整段说明挤进标题。
- 变更详情包含整个提交的新增／删除行数，以及逐文件的路径、增删行数和重命名前的路径。
- 正文展示摘要，最多 1200 字符、8 行；文件明细最多展示前 8 个。超出部分请打开图片下方的提交链接查看。
- 仅为即将发送的 Commit 请求详情，不在首次初始化或机器人离线时逐条查询。同轮相同仓库与凭据共用请求，成功获取的详情随待发队列保存，发送重试不再重复查询。
- 平台未提供统计或详情请求失败时，仍推送已有的提交内容，显示“增删详情暂不可用”；缺失的数字显示“—”，不会冒充 0。平台分页或截断文件列表时，不把当前页文件数当作完整总数。
- 文字样式以及图片渲染失败后的文字回退，同样包含正文和增删明细。

- 插件下载头像后将其内嵌到卡片中，渲染器不联网。头像只从各平台官方头像 CDN 下载，请求不带 Token，也不跟随重定向；只接受 PNG/JPEG/GIF/WebP 格式，大小不超过 200KB。
- 头像缓存 6 小时；下载失败的地址在 10 分钟内不再尝试。无法获取头像时显示作者首字母，不影响卡片生成。
- GitCode 的 Commit 接口不提供作者头像，GitHub 上未关联账号的 Commit 也没有头像，这两种情况都显示首字母。
- 部署环境无法访问头像 CDN 时，头像下载请求并行发出，卡片最多额外等待 5 秒（单个请求的超时），然后用首字母生成卡片；之后 10 分钟内不会再等待同一地址。

## 动态与投递语义

- 仅通知**新 Commit、新 Issue、新 PR、新 Release**。Issue/PR 的后续编辑、关闭、合并、评论和评审不会触发通知。两次轮询之间创建又被删除的内容无法发现。
- Commit 使用 SHA 和历史边界，不依赖作者日期。强制推送导致边界消失时，插件会保留旧进度并报错；确认后，取消并重新订阅可建立新基线。默认分支切换后的历史没有共同边界时，也按此处理。
- Release 排除草稿、包含预发布版，优先使用发布时间；GitCode 等平台未提供发布时间时，则使用创建时间。这类平台无法可靠识别很早就已创建、刚公开的草稿。
- 每个订阅的每类事件，每轮最多查询 3 页，每页 100 条。扫描状态会持久化，后续轮次继续扫描。为发现旧草稿的新发布，Release 会遍历全部发行版。请求仅在同一轮、仓库/分支/凭据范围相同时共享。
- 每批最多 10 条；图片批次含 Commit 时最多 3 条，避免正文与文件表格生成超长图。每个订阅每轮最多 3 批，未投递部分保留到后续轮次。消息包含仓库、类型、标题、作者、UTC+8 时间和链接，图片附带文字链接。每种事件的暂存上限和每个订阅的待发队列上限各为 20000 条；达到上限时会报告并暂停推进，不会静默丢弃。
- 消息与抓取进度一起持久化，发送返回 `ok: true` 后确认出队。账号离线或发送失败时，消息会保留以便重试，各群独立确认。发送前必须完成仓库权限验证，旧队列也遵循这一要求。
- 采用**至少一次投递**：如果进程在消息已发出、确认尚未落盘时崩溃，恢复后可能重发该批次。遇到 HTTP 限流时，遵守服务端指定的退避时间；普通网络/服务端错误采用指数退避。
- 检查状态保存在框架 KV 的 `plugin:git-plugin:` 命名空间。需要在重启后恢复状态时，应使用持久化 KV 驱动；使用框架的 `memory` 驱动时，关闭进程即丢失状态。

## 开发验证

框架发布到 npm 之前，需要先构建并链接本地框架 checkout，因为本插件的 tsc 需要读取框架的 `dist/*.d.ts`：

```sh
cd <框架 checkout>
pnpm install
pnpm run build

cd plugins/Git-Plugin
pnpm install --ignore-workspace
pnpm run link:framework   # 在 node_modules/@yunzai-ng 下建立指向框架的链接
pnpm run verify           # build → typecheck:test → lint → test
```

`link:framework` 按 `YZNG_FRAMEWORK` 环境变量 → `../yunzai-ng` → `../../yunzai-ng` → `../../code` 的顺序查找框架仓库。目录布局不同时，请设置该环境变量。

测试使用 vitest，测试文件与源码放在同一目录（`src/*.test.ts`），覆盖平台响应模拟、分页恢复、队列故障、权限、配置热变更、头像下载与过滤、图片回退，以及真实 NG 内核的面板 API 和消息路由集成测试。集成测试会将插件源码复制到系统临时目录，由 `createApp()` 加载，只监听本机临时端口；Git HTTP 和消息适配器均使用模拟，不访问实际群聊。

GitCode 接口依据：https://docs.gitcode.com/docs/apis/ ，API 基址为 `https://api.gitcode.com/api/v5`，使用 `Authorization: Bearer <token>`。GitHub 与 Gitee 分别使用 `https://api.github.com`、`https://gitee.com/api/v5`。遇到仓库重命名等重定向时，插件不会自动携带 Token 跳转，需要修改订阅地址。
