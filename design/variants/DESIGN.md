# Git-Plugin 卡片视觉备选

四组使用相同的仓库与 Commit、Issue、PR、Release 样例，供比较布局、配色与排版。打开 `preview.html` 查看总览，点击卡片进入单张 HTML。当前插件运行样式尚未切换。

| 方案 | 信息组织 | 视觉特征 | 建议用途 |
| --- | --- | --- | --- |
| A 青绿时间线 | 时间、节点、动态标题逐行排列 | 白底、青绿标识、宽松留白 | 重视阅读顺序和舒适度 |
| B 紧凑简报 | 仓库抬头、分类计数、紧凑条目 | 深蓝抬头、浅色正文、统计栏 | 日常群通知，优先推荐 |
| C 深色开发者 | 仓库路径、分支信息、编号条目 | 深蓝背景、等宽标识、薄荷绿重点 | 开发者群与深色视觉偏好 |
| D 纸感手记 | 刊头、仓库概览、编号文章 | 暖纸色、衬线标题、报刊式分隔线 | 版本发布和内容汇总 |

## 设计约束

- 技术：自包含 HTML/CSS，复用现有浏览器渲染方式，无新增依赖或 Tailwind 配置。
- 层级：仓库和标题优先；类型、编号与统计其次；作者、时间及来源辅助。静态通知卡片无交互主按钮。
- 间距使用 4、8、12、16、24、32、48、64；字号使用 12、16、20、24、30、36、48；字重 400/600。
- A/B 延续现有深蓝与青绿。C/D 补全冷灰和暖灰尺度，使用 Refactoring UI 的亮度二分、饱和度补偿与不超过 20° 的色相旋转算法。当前环境 Python 不可用，生成脚本以 JavaScript 实现同一算法。
- 颜色与对比度数据保存在 `design-tokens.json`，CSS 变量保存在 `tokens.css`。所有检查的正文配色组合达到 4.5:1，最低为 4.51:1。
- 640 像素以下切换窄屏布局：时间与标签移至条目上方，统计栏改为两列，标题保持自然换行。

## 已验证

使用本机 Edge 渲染，并人工检查总览和四张手机截图。四组分别在 375、800、1280 像素宽度下检查，总览另检查 375、1280、1600 像素；15 个组合均无横向溢出，结果见 `layout-checks.json`。

这些是固定内容的设计预览。选定方案接入动态数据时，还需复核长仓库名、超长标题、不同批次数量和空状态；本轮没有修改运行中的推送模板或发送真实消息。

重新生成 HTML 与配色数据：`node plugins/Git-Plugin/design/variants/generate.mjs`。

本工作区截图脚本：`node temp/git-variants-render.mjs`，使用已安装的 Puppeteer 和 Edge。
